# Build a first-class stateless Responses Provider

KiroaaS will implement the Responses API as a first-class protocol adapter in `python-backend/kiro/`, sharing the existing Kiro conversion, account, HTTP, and AWS Event Stream layers. The provider will implement the official Responses lifecycle rather than wrapping Chat Completions or copying KiroProxy's simplified handler; it will remain stateless by requiring clients to resend conversation input, and Client Tools will execute in the client while KiroaaS only transports Tool Calls and Tool Results. The first release exposes only response creation, not retrieval, deletion, cancellation, compaction, or stored input-item endpoints. This keeps protocol ownership explicit and avoids server-side conversation storage or false Hosted Tool capability claims.
